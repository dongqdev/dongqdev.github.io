### [1단계]**`Define View Entity`(자식 뷰)**
우리가 만든 주문 상세 자식 뷰인 `ZI_ORD_ITM`이 정확히 이 포지션입니다.

### [2단계]**`Define Root View Entity`(부모 뷰)**
한 비즈니스 오브젝트(BO)의 기둥이자 대가리가 되는 부모 Root 뷰, `ZI_ORD_HD`를 만드신 단계입니다.

**[3단계]`Behavior Definition`(행동 정의)**&**[4단계]`Behavior Implementation`(행동 구현)**
자바의 **Service Layer(비즈니스 로직)** 영역입니다.
화면에서 사용자가 `주문 생성`, `수정`, `삭제` 버튼을 누르거나 `결제 승인` 같은 커스텀 메서드를 호출할 때, 실제 ABAP 내부 logic 클래스(`금액 벨리데이션 체크`, `상태값 변경` 등)를 코딩하는 핵심 심장부입니다.

**[5단계]`Projection View`(프로젝션 뷰)**&**[6단계]`Behavior Projection`(행동 프로젝션)**


자바의 **DTO(Data Transfer Object)** 영역입니다.
1~2단계에서 만든 원본 인터페이스 CDS 뷰(`ZI_...`)를 알맹이로 두고, 그 위에 "특정 화면 전용 API DTO(`ZC_...`)"를 한 겹 더 씌우는 단계입니다. (예: 관리자용 화면 뷰, 사용자용 화면 뷰를 다르게 필터링해서 노출할 때 사용)
**[7단계]`Metadata Extension`(UI 어노테이션 정의)**
어떤 컬럼을 첫 번째 줄에 놓을지, 검색창은 뭘 만들지 어노테이션(`@UI.lineItem`)으로 UI 도면을 작성하는 단계입니다.

**[8단계]`Service Definition`(서비스 정의)**
우리가 방금 활성화한 `ZSD_ORD_LDG`입니다. 위에서 가공된 프로젝션 DTO 뷰들을 외부 API로 내보내겠다고 '문 열어주는' 컨트롤러 포지션입니다.

**[9단계]`Service Binding`(서비스 바인딩)**
이 게이트웨이에 **`OData V4 - UI`** 같은 구체적인 통신 프로토콜 규격을 믹스인해서 찐 서비스 URL(엔드포인트)을 활성화하는 단계입니다. 여기서 버튼 하나만 누르면 대망의 프리뷰 화면이 뜹니다.
